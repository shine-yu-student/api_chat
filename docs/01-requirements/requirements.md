# 需求规格（Requirements）

> 本文档定义项目的功能需求与非功能需求，每条需求附带可验收标准。
> 来源：产品需求原文 + 官方文档核实（[DeepSeek API Docs](https://api-docs.deepseek.com/zh-cn/)）。

## 1. 功能需求

### FR-1 界面整体仿 DeepSeek 网页端

**描述**：界面整体设计与 DeepSeek 网页端（chat.deepseek.com）类似：左侧会话边栏、顶部模型选择、中部消息流、底部输入区，欢迎页与消息页两种视图。

**验收标准**：
- [ ] 首屏呈现欢迎视图：居中 Logo/产品名、欢迎语、2~4 个推荐问题卡片
- [ ] 左侧边栏：顶部「新对话」按钮，下方会话列表（按时间倒序），底部用户菜单
- [ ] 对话页：顶部显示模型选择器与当前会话标题；中部消息流；底部输入区
- [ ] 输入区包含：多行输入框、深度思考开关、联网搜索开关、发送按钮
- [ ] 桌面端与移动端（≤640px）均有可用布局（移动端边栏可折叠）

### FR-2 模型选择（Flash / Pro）

**描述**：允许用户选择 DeepSeek-V4 Flash（`deepseek-v4-flash`）或 DeepSeek-V4 Pro（`deepseek-v4-pro`）。模型选择器位于顶栏，可随时切换；新消息按当前选择发送，历史消息保留其发送时模型。

**验收标准**：
- [ ] 模型选择器展示两个选项：`DeepSeek-V4 Flash`、`DeepSeek-V4 Pro`
- [ ] 切换后立即生效于下一条消息；当前会话标题栏与消息气泡可标识模型
- [ ] 每条消息记录 `model` 字段，会话恢复后仍能正确显示
- [ ] 若所选模型在 Responses API 暂不支持（当前为 Pro），发送时后端返回明确错误，前端在输入区上方以可读文案提示（见 FR-8），**不得静默失败**
- [ ] 后端存在 `MODEL_SUPPORT` 开关表，官方开放 Pro 后仅需改配置即可启用

### FR-3 设置界面与 API Key

**描述**：提供设置界面（入口：左侧边栏底部用户菜单 →「设置」），允许用户输入/修改 API Key。Key 持久保存在浏览器 localStorage，每次对话请求经自有后端代理转发，代理不落盘。

**验收标准**：
- [ ] 设置页含 API Key 输入框（password 类型，带明文切换按钮）与「保存」按钮
- [ ] 保存后写入 localStorage，刷新页面不丢失
- [ ] 未配置 Key 时，发送消息前前端拦截并提示前往设置
- [ ] Key 无效时（401）在界面明确提示「API Key 无效」，并引导检查设置
- [ ] 前端代码中不存在将 Key 发送给除自有后端代理以外的任何地址的路径

### FR-4 基于 OpenAI Responses API 对话

**描述**：所有对话请求通过 Responses API 完成：`POST https://api.deepseek.com/v1/responses`（OpenAI SDK `client.responses.create`），无状态 API，多轮上下文由客户端维护并全量发送。

**验收标准**：
- [ ] 请求体遵循 03-api-integration/responses-api.md 的构造规则（model/instructions/input/stream/tools/reasoning）
- [ ] 多轮对话正确：第二轮起携带完整历史（input items 列表），回答与上下文一致
- [ ] 流式输出逐 token 显示，无「等待结束后一次性输出」的情况
- [ ] 每个响应正确解析并展示 usage（输入/输出/缓存命中/推理 token 数）

### FR-5 深度思考开关

**描述**：输入区提供「深度思考」开关，可开启/关闭；开启时提供思考强度（低/高/最高）设置（默认高）。对应 Responses API `reasoning.effort` 参数：关闭 = `none`，开启 = `low|high|max`。

**验收标准**：
- [ ] 关闭时请求携带 `reasoning: {"effort": "none"}`，模型不输出思维链
- [ ] 开启时携带对应 effort，界面在最终回答前先展示可折叠的「深度思考」过程
- [ ] 思考过程流式滚动展示（`response.reasoning_text.delta`），完成后折叠为一行摘要（含用时）
- [ ] 思考模式开关与强度保存在设置中，可随会话记忆（每次新建会话沿用）

### FR-6 联网搜索开关

**描述**：输入区提供「联网搜索」开关。开启时请求携带 `tools: [{"type": "web_search"}]`（服务端执行），关闭时不携带任何 tools。

**验收标准**：
- [ ] 开启联网搜索后，请求体包含 web_search 工具；关闭后不包含
- [ ] 模型发起搜索时，界面出现「正在搜索网络…」状态（对应 `response.web_search_call.searching` 事件）
- [ ] 搜索完成后，回答正常流式输出；消息中展示搜索引用（来源角标，样式仿 DeepSeek 网页端）
- [ ] 多轮对话中，历史 web_search_call item 原样回传（服务端自动恢复搜索结果）
- [ ] 关闭联网搜索不影响深度思考等其他功能

### FR-7 上下文前缀缓存利用

**描述**：利用 DeepSeek 自动硬盘缓存，最大化 `usage.input_tokens_details.cached_tokens` 命中。

**验收标准**：
- [ ] 请求前缀（instructions + 历史消息）在会话内严格保持稳定：不改写、不重排、不插入
- [ ] instructions（= 会话 System Prompt 快照，见 FR-11）恒定置于请求最前；对话开始后快照锁定，任何路径不得修改
- [ ] 对话消息超过上下文预算时按「保留前缀、截断最旧」策略降级（详见 context-cache.md）
- [ ] 界面展示每条助手消息的 token 用量：输入（其中缓存命中）、输出、推理 token
- [ ] 第二轮起连续对话缓存命中率明显 >0（手工验证：连续 3 轮后 `cached_tokens / input_tokens` 通常 ≥90%）

### FR-8 错误处理与降级

**描述**：覆盖鉴权失败、余额不足、限流、上下文超限、网络中断等场景，提供可读提示与合理降级。

**验收标准**：
- [ ] 401 →「API Key 无效」；402 →「余额不足」；429 →「请求过于频繁，请稍后重试」
- [ ] 400（上下文超限）→ 提示并自动截断最旧消息后重试一次
- [ ] 流式中断（网络错误/`response.failed`）→ 保留已生成内容，展示「生成中断」与重试按钮
- [ ] 用户点击「停止」后，前端 AbortController 中止请求，后端同步取消上游请求
- [ ] 模型暂不支持（Pro）→ 明确文案提示，不重试

### FR-9 会话管理（本地）

**描述**：支持多会话：新建、切换、重命名、删除；会话与消息持久化到 IndexedDB；刷新页面后恢复。

**验收标准**：
- [ ] 侧边栏可新建/切换/删除会话；双击标题可重命名（或通过菜单）
- [ ] 每个会话记录：id、标题、模型、创建/更新时间、消息列表（含推理文本、搜索调用、用量）
- [ ] 刷新/重开浏览器后会话完整恢复，可继续对话
- [ ] 删除会话二次确认；删除后不可恢复

### FR-10 Markdown 渲染

**描述**：助手输出按 Markdown 渲染：标题、列表、表格（GFM）、代码块（语法高亮 + 复制按钮 + 语言标签）、行内代码、链接、LaTeX 公式；流式渲染不卡顿。

**验收标准**：
- [ ] 上述元素均正确渲染
- [ ] 代码块右上角显示语言名与复制按钮，点击复制成功
- [ ] 流式过程中 Markdown 增量渲染流畅（打字机效果，无整块闪烁）

### FR-11 System Prompt 库与会话级 System Prompt

**描述**：每个会话在对话开始前可指定自己使用的 System Prompt；对话开始（发送第一条用户消息）后锁定、不可更改。提供 System Prompt 库：用户可自行编写、存储、管理多条 System Prompt；系统内置一条基础 System Prompt（不可编辑/删除，作为默认兜底）。会话存储 System Prompt 内容快照，库条目的后续修改/删除不影响已开始会话。

**验收标准**：
- [ ] 新建会话默认选中内置基础 System Prompt；对话开始前可随时更换为库中任意条目
- [ ] 发送第一条消息后：UI 不再提供更换入口，仅显示只读的 System Prompt 名称；请求中 `instructions` 恒等于该会话快照内容
- [ ] 库管理（设置内）：新建/编辑/删除自定义条目（删除有确认）；内置条目不可编辑/删除
- [ ] 库条目可「设为默认」，新建会话预选默认条目；默认条目被删时自动回退内置基础 Prompt
- [ ] 修改/删除某库条目后，引用它的已开始会话的 `instructions` 保持不变（快照隔离，可经 DevTools 网络面板验证）
- [ ] 内置基础 Prompt 恒存在，库自定义条目全删后系统仍可用
- [ ] 旧版全局「自定义指令」设置内容自动迁移为库中一条自定义条目（一次性）

### FR-12 对话分支（编辑消息 / 重新生成）

**描述**：允许编辑对话中以往的任何一条输入消息（user 消息），编辑后创建对话分支并从新内容自动重新生成；对任意一条 assistant 消息点击「重新生成」同样创建新分支。分支之间可自由切换查看，旧分支内容保留。消息以树结构存储（parentId），会话记录当前活动路径（activeLeafId）。

**验收标准**：
- [ ] 任意 user 消息可进入编辑态（内联 textarea），保存后：新 user 消息（含新内容）插入当前路径，其后自动生成新 assistant 回复
- [ ] 编辑/重新生成后，被替换的消息及其后续消息（旧分支）**完整保留**，可切换回查看
- [ ] 分支点（同一父消息有多个子分支）下方显示分支切换行：当前分支高亮、其他分支可点击切换
- [ ] 切换分支后路径随之变化，继续发送的新消息追加在**当前**分支末端
- [ ] 重新生成对已完成/失败/停止/截断的 assistant 消息均可用，每次生成新分支
- [ ] 编辑后自动重新生成的内容与旧分支互不影响（各自独立生成）
- [ ] 流式生成中不可编辑/切换分支/重新生成（输入区禁用规则沿用）
- [ ] 刷新后分支结构完整恢复（parentId 树与 activeLeafId 持久化）；旧版无分支会话自动线性迁移

### FR-13 流式渲染性能（卡顿修复）

**描述**：流式接收过程中不得出现主线程卡顿（表现为 DevTools 无响应、CPU 占满）。实现帧级节流：同帧内多个 delta 累积后批量更新状态；未变化的消息不重新渲染、不重新解析 Markdown。

**验收标准**：
- [ ] 长文本流式输出（≥5K token）期间页面滚动、按钮点击均流畅（DevTools Performance 无长任务 > 100ms）
- [ ] 流式期间仅正在生成的消息重渲染，历史消息组件不执行（React DevTools Profiler 可见）
- [ ] 停止/中断后已生成内容完整（累积 delta 全部落盘）

### FR-14 侧边栏可调宽度与收起

**描述**：桌面端左侧边栏宽度可自由调整（拖拽右缘手柄），并可完全收起；收起后顶栏出现汉堡按钮随时展开。宽度与收起状态持久化到设置（localStorage），刷新后保留。移动端保持抽屉行为不变（ui-design.md 4.7）。

**验收标准**：
- [ ] 桌面端边栏右缘有拖拽手柄（`cursor-col-resize`），拖动实时调整宽度，范围 200~480px，松手后状态持久化
- [ ] 点击收起按钮（或手柄处提供的收起入口）后边栏完全隐藏，主内容区占满；顶栏左侧出现汉堡按钮可展开
- [ ] 刷新页面后宽度与收起状态恢复
- [ ] 拖拽/收起不影响流式对话（生成中可操作，不触碰会话数据）
- [ ] 移动端（<768px）行为不变：抽屉 + 遮罩开合，宽度 ≤ 85vw

### FR-15 对话数据导出/导入

**描述**：将全部会话（含消息、分支、用量、System Prompt 快照）与用户自定义 System Prompt 库导出为 JSON 备份文件（本地下载）；可导入备份文件恢复/合并数据。备份文件含 `format`/`version` 标识，便于版本演进。导入时若与本地存在同 id 的会话或库条目，**跳过并保留本地**（不覆盖）。

**验收标准**：
- [ ] 导出入口在侧边栏用户菜单（「导出数据」）：下载 `deepseek-chat-backup-YYYYMMDD-HHmmss.json`，内容含全部会话与自定义 System Prompt（内置条目不导出），完成后有成功提示
- [ ] 导出文件结构：`{ format: "deepseek-chat-backup", version: 1, exportedAt, sessions: Session[], prompts: SystemPrompt[] }`
- [ ] 导入入口同菜单（「导入数据」）：选择 JSON 文件后先展示确认对话框（将导入 N 个会话、M 条 Prompt，说明同 id 冲突项将跳过），确认后执行
- [ ] 格式校验：非本应用备份文件（format/version 不符）或非法 JSON 时给出明确错误提示，不写入任何数据
- [ ] 导入后会话立即出现在边栏并可切换查看；刷新页面后仍在（已持久化）
- [ ] 同 id 会话/条目被跳过且本地数据不被覆盖；导入完成后提示「导入 N、跳过 M」
- [ ] 导入期间若正在流式生成，先停止生成再导入；导入不导入设置项与 API Key

## 2. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-1 | 性能 | 首字符延迟（TTFB）目标 < 3s；流式逐 token 呈现；本地 UI 无阻塞 |
| NFR-2 | 安全 | API Key 仅存 localStorage 与后端内存；后端不写日志、不落盘；所有请求经代理，不直连 DeepSeek |
| NFR-3 | 兼容 | 最新版 Chrome / Edge / Firefox / Safari；移动端可用 |
| NFR-4 | 可维护 | TypeScript 严格模式；核心逻辑（input 构造、事件解析）单元可测 |
| NFR-5 | 成本 | 通过前缀缓存策略降低重复输入 token 计费（见 FR-7） |
| NFR-6 | 健壮 | 网络抖动时流式会话不崩溃，可恢复；超时（60s 无数据）自动中止并提示 |
| NFR-7 | 可访问 | 主要交互（发送、切换模型、开关）支持键盘操作；对比度满足基本要求 |

## 3. 明确不做（范围外）

- 不做用户账号/服务端会话存储（无后端数据库），会话仅存本机
- 不做文件上传/图片理解（Responses API 输入 items 不支持图片，输入图片会被替换为占位文本）
- 不做多用户/分享功能
- 不做移动端原生 App
- 不实现自有 web_search（必须使用服务端 `web_search` 工具）
